使用说明

适用于 Live2D Param 0.0.1 alpha.1 · 需要 Cubism Editor 5.4 alpha1 及以上

这是个什么工具

Live2D Param 是一个给 Live2D 建模打下手的小工具： 把 Cubism Editor 里的参数组列表读进来，在工具里批量改颜色、改名字、跑配色脚本， 确认没问题之后，再一次性写回 Editor。

它解决的事情说白了就一件 —— Editor 里给参数组上色是一个一个点的重复劳动， 这个工具让你批量做完、一次性提交。

现在能做到的

  • 读取参数组（含嵌套组）和变形器结构 —— 纯读取，不动模型；
  • 参数组批量改色：预设色、自定义取色（三角调色盘 / 色相圆环 / 吸管）、精确填 RGB；
  • 参数组改名；
  • 撤回 / 前进：改错了随时退回来；
  • 保存 / 载入配色方案：存成 JSON，换个模型也能接着用；
  • 配色脚本：用一份声明式 JSON 描述「什么样的参数组上什么颜色」，自带 3 个官方脚本；
  • 记录窗口：所有操作都有记录，可以下载成只读 txt。
还是 alpha 版本。 当前版本 0.0.1 alpha.1，非常早，站长自己都还不知道有什么 bug。 用之前请先看一眼下面的「已知限制」，用出问题后果自负 qwq

系统要求

项目 要求
操作系统 Windows 10 / 11（64 位）
运行环境 .NET Framework 4.x —— Win10 / 11 系统自带 4.8，不用额外装任何东西
Cubism Editor 5.4 alpha1 及以上，且处于建模模式（见下）

Cubism 版本限制

  • 最低 Editor 5.4 alpha1：这套「外部应用程序集成」的 API 是那时候才有的，更低的版本连不上；
  • 必须处于建模模式：读取和写入用的都是编辑类 API，只在建模模式下有效 （不然会出现「读取成功，但一个参数组都没有」）；
  • 集成开关要打开：菜单 [文件] → [外部应用程序的集成设置] 里把连接开关打开。

安装

  1. 到 Releases 下载 Live2D-Param-v0.0.1-alpha.1-Setup.exe（文件名里的版本号跟着版本走）；
  2. 双击运行，点「安装」；
  3. 完成 —— 桌面和开始菜单里会出现快捷方式。

安装包很小（不到 400 KB）：主程序和卸载程序都是用系统自带的 .NET 编译器编出来的原生小程序， 安装时不会顺手给你装运行时、也不会塞一堆依赖。

卸载

两种方式都行：

  • 「设置 → 应用 → 已安装的应用」里找到 Live2D Param 0.0.1 alpha.1，点卸载；
  • 或者双击安装目录里的 Uninstall.exe。

卸载会保留什么、删掉什么

  • 保留 %APPDATA%\Live2D Param： 里面存着 Editor 给的访问令牌和你的偏好设置，所以重装之后不用再去 Editor 里重新授权一遍。 想彻底清干净就手动删掉那个目录；
  • 删除安装目录里的所有文件、子文件夹、快捷方式、卸载信息 —— 卸载就是清空安装目录；
  • 只有两个文件夹留着：你自己放在那里的 配色方案\ 和 脚本\。
因为卸载会清空整个安装目录，重要的东西别扔在根目录或者别的文件夹里，除非你不想要了。 放在 配色方案\ 和 脚本\ 里的东西才会被留下来。

命令行参数

（安装包的文件名里带版本号，比如 Live2D-Param-v0.0.1-alpha.1-Setup.exe，下面简写成 Setup.exe） 

Setup.exe                          图形界面安装
Setup.exe /S                       静默安装
Setup.exe /S /NODESKTOP            静默安装，且不建桌面快捷方式
Setup.exe /DIR="D:\somewhere"      指定安装目录
Setup.exe /?                       显示帮助

Uninstall.exe                      图形界面卸载
Uninstall.exe /S                   静默卸载

静默模式没有界面，过程会写进 %TEMP%\Live2DParam-Setup.log，退出码 0 表示成功。

一、在 Editor 里准备

  1. 启动 Cubism Editor 5.4（或更高），打开一个模型，切到建模模式；
  2. 打开菜单 [文件] → [外部应用程序的集成设置]；
  3. 把连接开关打开，看一眼端口号 —— 默认 22033，一般不用改。

二、连接

  1. 在 Live2D Param 左下角的「Editor 端口」框里填上刚才那个端口（默认 22033），点「连接」；
  2. 这时 Editor 会弹出一个链接许可对话框，把里面的 「权限」 和 「编辑」 两个都勾上。
两个都要勾。只勾「权限」的话，连读取参数组都会失败。
授权只要授一次。令牌会存到 %APPDATA%\Live2D Param\token.txt， 下次点「连接」就不用再勾了。（明文保存，公用电脑上请留意这一点。）

三、读取参数组

点工具条上的 「读取参数组」，列表里就会按层级列出所有参数组 （嵌套组会递归展开），每行显示它当前的颜色和名字。

「读取」是纯读操作：不会改动模型，也不会往 Editor 的撤销历史里塞东西。

四、改颜色 / 改名

先说清楚：这一步改的只是工具里的列表，还没写进 Editor。 改过的行会变成浅黄色底，右边「待应用」列写明了这行改了什么。

预设色与自定义取色

  • 点 「改色」列的色块 → 弹出预设色窗口（3×3 色格）：点某个色格就直接选中；
  • 点这个窗口右下角的 「自定义…」 → 打开三角取色窗口：
    • 中间的三角形调色盘（固定不转），外面一圈是色相圆环，拖动就能换色；
    • 下面是亮度条（白 → 当前色 → 黑），拖它调明暗；
    • 下方还有 RGB / HSV 数值框，想精确填就填数字；
    • 以及吸管：点一下就能到屏幕上任意位置取色（左键取色，右键取消）。

批量改

  • 先在列表里选中若干行（Ctrl 点选、Shift 连选），再点 「设为颜色…」；
  • 一行都不选 = 作用于全部；
  • 想一次刷完，也可以直接用配色脚本。

改名字

双击 「名称更改」列，直接改。

这个版本不支持改参数组的 ID（NewId）：API 是支持的，但界面故意没做， 避免误操作破坏模型。

撤回与前进

  • Ctrl + Z 返回上一步，Ctrl + Y 前进一步；
  • Ctrl + Shift + Z 放弃全部更改；
  • 工具条上也有「返回上一步 / 前进一步」两个图标按钮。

一次「设为颜色…」、一次「载入方案」、跑一整个脚本，都各算一步。

五、应用更改

点 「应用更改」，前面攒下的所有「待应用」改动才会真正写进 Editor。

  • Editor 会弹出一个编辑对话框并把界面临时锁定 —— 处理过程中不要操作 Editor；
  • 写完之后工具会把列表基线更新成新值，那些浅黄色底恢复正常；
  • 中途想放弃：就在 Editor 那个对话框里点「取消」，所有改动会被整体回滚 —— 你选的颜色仍然留在列表里，可以直接重试；
  • 万一中途出错，工具会自动发一次回滚请求，同样不动你选好的颜色； 连回滚都失败的话，记录窗口里会明确警告，请在 Editor 里按 Ctrl + Z 检查。
不会写错模型。真正写回之前，工具会再确认一次 Editor 里的模型是不是读取的那个 —— 不是同一个就直接停下，让你重新读取，而不是往错误的模型上写。

记录窗口

点工具条上的 「记录」打开独立窗口：连接、读取、应用、出错都记在里面。 窗口可以复制、清空，也可以下载为 txt —— 下载出来的文件会被设成只读，省得手抖把现场改掉。

反馈 bug 的时候，把这份记录一起发过来最有用。

变形器视图（只读）

左边有个视图切换（参数组 / 变形器），两块卡片占同一格，切一下就换过去。

  • 变形器按树展示（嵌套的能展开），选中一个，右边属性面板显示它的名称 / ID / 类型 / 层级；
  • 这个视图是只读的，而且不需要 Editor 的「编辑」权限， 也不会弹那个会锁定 Editor 的编辑对话框；
  • 每个变形器只有这几个字段可用：Name / Id / Type / Children。 倍率、角度、顶点、不透明度、标签颜色都不在这个接口里（要拿得另外调接口）， 所以属性面板里不会显示 —— 不是漏做了。

脚本窗口

点工具条上的 「脚本」打开：

  • 左边是脚本列表，每行右边有一枚「官方 / 我的」小标签；
  • 右边是选中脚本的说明和规则明细：逐条列出「什么条件 → 什么颜色」， 每条带一个小色块，有渐变的还会画一条渐变预览；
  • 选中一个，点 「运行」，它就按规则把颜色填进列表 （同样只是「待应用」，不会直接写进 Editor）。

官方脚本与自己的脚本

脚本就是一份 JSON 文件，两类脚本都放在同一个「脚本」文件夹里 （在软件安装目录下，跑过一次程序就会出现）。

来源 说明
默认自带（官方） 名字是默认的那 3 个：按名字上色.json、层级循环上色.json、层级渐变.json。 它们内嵌在 exe 里，每次启动按当前版本覆盖写出。
你自己的 名字不跟默认撞的 *.json，丢进「脚本」文件夹就会被列出来。
想改官方脚本？给它改个文件名（例如 层级渐变-我的.json）—— 它立刻变成「你自己的」脚本，程序再也不会覆盖它。

脚本怎么写

脚本是一份声明式 JSON，描述「什么样的参数组上什么颜色」。 它特意不是可执行代码：本工具只用了系统自带的 .NET 编译器，跑不了 JS / Python 这类脚本语言。 好处也很实在 —— 规则写错最多是「不生效」，不会在你电脑上执行别的东西。 

{
  "version": 1,
  "name": "按名字上色",
  "description": "显示在窗口里的一句话说明",
  "rules": [
    { "name": "*眼*", "color": "blue" },
    { "id": "ParamGroup*", "depth": 0, "cycle": ["red", "green", "blue"] },
    { "minDepth": 1, "color": "#8AC1FF" },
    { "name": "*", "gradient": "ask" }
  ]
}

一条规则 = 匹配条件 + 上色方式。

匹配条件

字段 含义
name 匹配参数组名称，支持 *（任意多个字符）和 ?（一个字符）；不写 = 不限
id 匹配参数组 ID，写法同上
depth 只匹配正好在第几层的组（0 = 顶层）
minDepth 只匹配第几层及更深的组

匹配不区分大小写；中文关键词直接写就行 —— *手* 能同时命中「手臂」和「手指」。

上色方式

字段 含义
color 上什么色：red / orange / yellow / green / blue / purple / gray / default， 或者 "#RRGGBB" 自定义色
cycle 命中多个组时按顺序轮流用这几个颜色（数组，元素写法同 color）
gradient 命中多个组时按顺序在这些色标之间平滑渐变：写 ["#RRGGBB", …] 就是固定色标； 写 "ask" 则运行的时候弹个小窗口让你现选一个颜色
  • color / cycle / gradient 三选一；
  • 规则从上往下匹配，第一条命中的说了算；一条都没命中的组保持原样；
  • 脚本名字默认取文件名（不含扩展名），写了 name 就以 name 为准。

关于 "gradient": "ask"

选完颜色，工具会从白一路铺到它，最后一组正好是所选的颜色； 色带只截取「白 → 本色」这前半段，不会往黑里走。 选色那个小窗口用完就关掉、不会留着，取消就等于这个脚本没跑。

运行脚本会发生什么

  • 结果只是填进列表当「待应用」改动（和「载入方案」是同一条路子）， 不会直接写进 Editor —— 看过没问题再点「应用更改」；
  • 作用于全部参数组：脚本是批量规则，不是「设为颜色…」那种只改选中行的行为；
  • 整个脚本算一步撤回：Ctrl + Z 一次退掉；
  • 跑完脚本窗口会自己关掉，这一点由窗口里「运行后关掉窗口」那个勾选框决定 （默认勾上；取消勾选就能连着跑好几个脚本）。这个勾选会记住，下次打开还是上次的样子；
  • 脚本打不开（JSON 写错了）时，列表里会把它标成红色并显示具体错误，不影响其它脚本；
  • 没能跑起来时（还没读参数组、一条都没命中、或者取消了选色）窗口不会关，会弹一句说明。

保存与载入

  • 调好颜色之后点 「保存方案」，会把当前这套配色存成一份 JSON （默认就放在安装目录的 配色方案\ 里）；
  • 下次、或者换一个模型，点 「载入方案」把它读回来：颜色会填进列表当「待应用」， 确认后再点「应用更改」；
  • 一个方案里记的就是「参数组 → 颜色 / 名字」，所以它能当模板反复用。

跨模型复用

可以。载入时先按参数组 ID 匹配，ID 对不上时再按名称匹配。

没匹配上的条目会被忽略 —— 界面上会告诉你有几条没匹配上，看了数字你就知道要不要手动补。

常见问题

点「连接」提示连接失败 / 超时？

按顺序检查这五件事：

  • ① Editor 是不是 5.4 alpha1（或更高）；
  • ② Editor 有没有打开模型；
  • ③ 菜单 [文件] → [外部应用程序的集成设置] 里的开关有没有打开；
  • ④ 两边端口号是不是一致（默认 22033）；
  • ⑤ 端口是不是被别的程序占了（见下一条）。
怎么知道 22033 是不是被别的程序占了？

在 PowerShell 里执行：

netstat -ano | Select-String "LISTENING" | Select-String ":22033"

如果列出了进程，但它不是 Cubism Editor（Editor 的进程名是 java.exe， 路径在 ...Live2D Cubism 5.4 alpha\app\jre\bin\ 下），那就是被别的程序占了。这时：

  • 在 Editor 的集成设置对话框里把端口改成别的（例如 22035）；
  • 在本工具顶部的「Editor 端口」框里填同样的数字。

也可以用它确认占用者到底是谁： Get-Process -Id <PID> | Select-Object ProcessName, Path

连上了，但一直停在「等待授权…」？

需要在 Editor 的集成对话框里勾选本程序。注意要勾两个：「权限」和「编辑」。 只勾「权限」的话，读取参数组也会失败。

提示「无法开始编辑」？

最常见的就是上面那条 —— 没勾「编辑」权限。其次确认 Editor 处于建模模式， 以及没有另一个编辑会话正在进行中（比如另一个程序也连上了）。

读取成功，但一个参数组都没有？

基本可以确定 Editor 不在建模模式。编辑类 API 只在建模模式下有效。

应用之后颜色没变？

看「记录」窗口。如果写着「已被用户在 Editor 中取消」，说明编辑对话框被点了取消、 改动已经整体回滚 —— 你选的颜色还在列表里，重新点「应用更改」即可。

会不会误改我别的参数组？

不会。应用时只发送你明确改过的组；而且写回前会重新确认一次模型， 发现 Editor 里的模型跟读取时不是同一个就停下来要求你重新读取， 而不是往错误的模型上写。

能跨模型复用配色吗？

可以 —— 用「保存方案」存成 JSON，在另一个模型上「载入方案」。 先按参数组 ID 匹配，ID 对不上时按名称匹配，详见「配色方案 → 跨模型复用」。

杀毒软件会报毒吗？

不应该。这是一个用系统自带编译器编译的原生小程序（主程序约 200 KB）， 没有加壳、没有自解压、没有 PyInstaller 之类的打包器 —— 那类特征才是杀软误报的常见来源。 要是真报了，欢迎把截图发来。

已知限制

  1. 只支持 Cubism Editor 5.4 alpha1 及以上，且必须处于建模模式。
  2. 只有 Windows 版。核心逻辑和界面没有强绑定，但界面用的是 WinForms。
  3. 预设色的色块是按 Editor 取色界面的截图采样画的：预设色的实际 RGB 由 Editor 内部决定， API 不返回。写回时只发送预设的名字，最终颜色仍以 Editor 为准； 只有 LabelColorType = "Custom" 时，颜色才由 #RRGGBB 精确决定。
  4. 应用期间 Editor 会被锁定，这是 Editor 侧的设计（弹出模态编辑对话框），不是本工具造成的。
  5. 本版本不支持修改参数组的 ID（NewId）。
  6. 模型特别大时，第一次读取会稍慢（GetParameterStructure 的响应本来就大）。
  7. 令牌以明文存在 %APPDATA%\Live2D Param\token.txt （和官方 Python 样例的做法一致）。它只能用来连本机的 Editor，但共享电脑上请留意。
  8. 端口可能被别的程序占用：Editor 默认用 22033，被占了 Editor 就监听不了， 工具也就连不上 —— 两边都改成同一个新端口即可。
