## 二、现在最大的结构问题：**两套导航**

| | 首页 | 子页面 |
| --- | --- | --- |
| 导航位置 | **左侧浮动侧边栏**（可收起）| **顶部横向导航栏**（`common.js` 注入）|
| 菜单内容 | 首页 / 插画 / 周边 / 动态 / 关于▾ / Live2D / 设置 | 插画 / 周边 / 动态 / Live2D / 关于▾（**隐藏当前页**）|
| 用户入口 | 左下角用户区（昵称 + 签名）| 无 |
| 页脚 | 无 | 三列链接（使用说明 / bilibili / github…）|
| 视觉风格 | 插画背景 + 浮层 | 白底 + 细边框 |

**导致的问题**：
1. 两套导航内容不一致 → 用户在子页面找不到「设置」，在首页找不到「GitHub / 关于站长的链接」
2. 从子页面回首页只能点左上角「星月」logo，不直观
3. 子页面之间风格统一（白底），首页是插画全屏——**割裂感**明显
4. 每加一个页面要改两处导航（`index.html` 侧边栏 + `common.js` 的 `PAGES` 数组）

## 三、需要拍板的问题（逐条回答即可）

### ① 主页（index.html）以后放什么？

| 方案 | 说明 |
| --- | --- |
| **A. 保持现在** | 全屏 Live2D 角色 + 聊天气泡 + 输入框 = 「和角色聊天」为主 |
| **B. 改成门面页** | 大背景 + 角色立绘 + 一句话介绍 + 几个入口按钮，**聊天挪到独立页面** |
| **C. 混合** | 首页展示为主，右下角保留一个小聊天窗（可展开成全屏聊天）|
| **D. 其他** | 你描述 |

你现在的主页是 **A**。

### ② 导航怎么统一？

| 方案 | 说明 |
| --- | --- |
| **A. 全站顶部导航** | 去掉首页侧边栏，所有页面用同一套顶部导航（改动中等，风格统一）|
| **B. 全站左侧侧边栏** | 子页面也加左侧侧边栏（改动大，但沉浸感强、适合"角色陪伴"类站点）|
| **C. 保持两套** | 首页侧边栏 + 子页顶栏（现状，不推荐：加页面要改两处）|
| **D. 首页无导航 + 全屏沉浸，子页统一顶栏** | 首页只留左下角用户区，导航靠"进子页后才出现" |

### ③ 哪些页面要动？

### ④ 要不要「单页应用化」？

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 保持多页（现状）| 简单、零构建、每个页面独立 | 每次跳转整页刷新（Live2D 要重新加载模型，慢）|
| 改成 Hash 单页 | 切换瞬间完成、Live2D 不重载、状态保持 | 代码要重组，分享某个"页面"的链接变复杂 |

> 💡 折中做法：**首页 + 聊天 + 关于** 留在单页里切换，重内容页（插画、Live2D 下载）保持独立多页。
