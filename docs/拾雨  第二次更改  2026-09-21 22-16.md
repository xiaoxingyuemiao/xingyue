### 2. 修掉的两个真 bug

| Bug | 现象 | 根因 |
| --- | --- | --- |
| 首页聊天 | 点 ➤ 不发送；点左边角色按钮反而把输入框的字发出去 | `querySelector(".chat-input button")` 拿到的是文档顺序第一个按钮（角色按钮） |

### 5. 画廊布局固定 + 比例重排

- 原来每次刷新都重新随机（`Math.random()`）。现在用**固定种子的伪随机**（`LAYOUT_SEED = 20260921`）：种子不变 → 画框比例、位置、间距、花草分布每次完全一样。
- 想换一整套布局，改这一个数字即可。
- 比例经两轮调整后定为：**9:16 / 1:1 / 16:9 / 20:9 各 4 个**（共 16 个画框），数量写在一个 `SLOTS` 配置里，总数自动算。**第 3 个画框固定是 9:16 手机竖屏**，并且洗牌后会强制把它换到第 3 位，所以三种比例的数量一个都不会变。

### 6. 画廊挂上 `images/` 里的图

- `ARTWORKS` 从「编号 → 路径」改成数组，每张写清宽高；代码按**比例最接近**自动分配画框，某种比例的画框配额占满后，剩下的图**不挂**（保持木色占位）。
- 实际挂上 6 张：`zhushitu.jpg` → 16:9、`supingbeijing.jpg` → 9:16、4 张正方形图（两张立绘 + 两张背景图）→ 4 个 1:1 画框。**正方形图正好一对一，不用裁剪**。
- 20:9 那 4 个空着，因为 `images/` 里没有比 16:9 更宽的图。

### 7. 自动预览页：临时幻灯片

- 把 `images/` 里**全部 11 张**图按顺序循环播放，每张停留 **3~6 秒（每张都随机）**。
- 切换效果共 **17 种**随机挑：八向翻折（上/下/左/右 + 四个角）、八向平移、慢慢淡出淡入。
- 首屏优化：第一张加载完就开播，其余后台预加载；切换前会检查下一张是否加载完，没加载完就等 —— 免得翻折的是一张空白。

### 8. 翻折方向统一向后

站长发现翻折「有的向后、有的向前、有的不动」。根因有两个：

1. 「进入」和「离开」用了**互为相反**的旋转角 → 一边向后另一边必然向前；
2. 四个对角方向的**旋转轴和折线没对上** → 看起来像没动。

改法：每个方向只留一个「向后」角度，进入用它→0、离开用 0→它；对角方向的轴改成垂直于对应对角线。
符号不是猜的 —— 拿元素四个角做罗德里格斯旋转，看四角平均 z 是正是负来定（CSS 里 Z 轴指向观众，负 = 向后）。

### 9. 预览页背景挪用「周边」页

- 把周边页那套深色主题搬过来：底色 `#06080d` + 顶栏/页脚半透明深色毛玻璃 + 浅色文字。
- **只要背景，不要它的文字**（那边「暂时什么都没有呢 / 看看星星吧」没有带过来）。
- 粒子也带上了：把 `zhoubian.html` 里那段 420 行的粒子代码**原样**抽成 `assets/js/mesh-bg.js`（逐字比对 17030 字符完全一致），预览页加 `<canvas id="mesh">` 引用它。
- 层次：粒子 `z-index: 0`、内容层 `z-index: 1` —— 粒子**可以被幻灯片盖住，但照常运行**。

## 三、这一轮的验证方式变了

从这一轮起 `read_image` 不可用了（模型不接受图片输入），所以渲染类改动**不再靠截图看**，改成数值验证：

| 验证对象 | 怎么验的 |
| --- | --- |
| 画廊布局是否固定 | 加载两次，逐项比对 16 个画框的比例/位置/尺寸 + 127 个花草 |
| 画廊比例分配 | 读每个画框的 `data-ratio` 统计分布 |
| 幻灯片是否在播、是否循环 | 60 秒连续采样，记录每次切换的图片与效果，验证跑完 11 张后回到第 1 张 |
| 翻折是否统一向后 | 读动画中点时刻的 3D 变换矩阵，算元素中心的 z 位移（16 项全为负） |
| 粒子是否在运转 | 隔 0.9 秒采两帧 canvas 像素比对（亮点数 17435 → 17874） |
| 背景配色是否正确 | 读计算样式（`rgb(6, 8, 13)` / `rgba(6, 8, 13, 0.55)` / `blur(10px)`） |
