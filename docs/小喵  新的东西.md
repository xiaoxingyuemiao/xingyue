## 七、云端同步（这一步是大工程）

**为什么做**：让"个人页面的东西跟着账号走"——换设备 / 换浏览器登录后，昵称、头像、角色、对话都还在。

### 数据库（Supabase）

| 表 | 存什么 |
| --- | --- |
| `uid_pool` | 编号池：**1000~3000 正常分配**，**1~999 保留**（测试用）|
| `profiles` | uid、昵称、头像、签名 |
| `user_settings` | API 提供商 + 我的角色（秘钥可选择加密后存）|
| `chat_sessions` | 对话记录（按角色分组）|

**uid 规则**：新用户注册 → 触发器从 1000 起**顺序**分配（1000、1001、1002…）；**注销 → 号还回池子**，下一个新用户优先拿到空出来的号。

**安全设计**：
- 三张表都开 **RLS**（只能读写自己那一行）+ **GRANT**（表级权限）
- `uid_pool` 客户端完全访问不到
- 秘钥默认不上云；勾选后 **AES-GCM 加密**才上传

### 前端

- `assets/js/cloud.js`（新模块）：资料 / 设置 / 对话的云端读写 + 秘钥加解密 + 注销
- 登录后自动拉云端资料（uid → 决定默认名字）
- 保存资料 → 本地 + 云端各一份
- 改角色 / 聊天 → 后台静默同步（对话防抖 3 秒）
- **换账号自动清本地残留**（防止看到上一个账号的昵称 / 头像）
- **注销账号**：需要输入 **密码 + 邮箱验证码**，两项都通过才删；删完释放 uid、级联删数据、清本地

## 八、踩过的坑（都修好了）

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `42501 permission denied for table profiles` | 有 RLS 策略但没给**表级权限** | 补 `grant ... to authenticated` |
| `23502 null value in column "uid"` | 测试账号在建表**之前**创建，没有 profiles 行 | 补一段「补齐历史用户」SQL |
| 注销 405 | Supabase 不允许前端直接删自己账号 | 改用数据库函数 `delete_own_account()` |
| 换账号看到上一个账号的资料 | 本地 localStorage 残留 + 兜底合并 | 登录时按 user_id 判断，换账号先清本地 |
| 验证码输入被吃掉 | 我按 6 位限制，实际是 **8 位** | 放宽到 4~10 位 |
| 注销提示"（也可以改用验证码登录）" | 文案错位 | 改成「密码或验证码不正确，请检查后重试」|
