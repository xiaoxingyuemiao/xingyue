# 云端同步（个人页面的数据跟着账号走）

> 目标：换设备 / 换浏览器登录后，**昵称、头像、签名、角色、对话记录都还在**。
> 做法：用 Supabase 的数据库（免费额度足够），配合行级安全保证「每个人只能看自己的」。

---

## 一、你要做的一步：执行数据库脚本

1. 打开 Supabase 后台 → 左侧 **SQL Editor** → **New query**
2. 打开本仓库的 **`tools/supabase-schema.sql`**，把**全文**复制粘贴进去
3. 点 **Run**
4. 看到 Success 就完成了 ✅（脚本可以重复执行，不会报错）

> 脚本会建 4 张表 + 2 个触发器 + 行级安全策略 + **表级权限（GRANT）**，详见文件里的注释。
>
> ⚠️ **如果执行后仍报错 `permission denied for table xxx (42501)`**，说明表级权限没给上：
> 单独把脚本第 ⑧ 段（`grant ... to authenticated;` 那几行）再执行一次即可。
> 原因：RLS 策略管"行"，`GRANT` 管"表"，新版 Supabase 不会自动授予表权限。

## 二、数据分别存在哪

| 数据 | 存哪 | 换设备能带走吗 |
| --- | --- | --- |
| 昵称 / 头像 / 签名 | ☁️ 云端 + 本地 | ✅ |
| **uid**（「小窝第 N 成员」的编号）| ☁️ 云端（`uid_pool`）| ✅ |
| 我的角色（含模型配置）| ☁️ 云端 + 本地 | ✅ |
| 对话记录 | ☁️ 云端 + 本地 | ✅ |
| **API 秘钥（Key）** | 默认 📴 只在本地；**勾选后 ☁️ 加密上云** | 看勾没勾 |
| 登录凭证 | 📴 只在本地 | —— |

**API 秘钥为什么默认不上云**：它是"能花钱的东西"，一旦上云就等于存在别人服务器上。
所以做成**用户自己勾选**（个人中心 → API 设置 →「同步秘钥到云端」）：

- **不勾**（默认）：Key 只留浏览器本地，换设备要重新填 —— 最安全
- **勾上**：Key 用 **AES-GCM 加密**后才写进 `user_settings.apiKeyEnc`，
  密钥由 `SHA-256("xingyue-field-v1|" + user_id + "|" + email)` 派生，存成 `v1.<base64(iv+密文)>`
  服务端拿到的是密文（明文永不入库），但**安全强度仍低于不上云** —— 由用户自己权衡

（实现见 `assets/js/cloud.js` 的 `pushSettings` / `pullSettings` 与 `encryptText` / `decryptText`。）

## 三、uid 是怎么分配的（对应「小窝第 N 成员」）

```
uid 池：1000 ~ 3000              ← 预先生成，记录每个编号被谁占用
        （1 ~ 999 是「保留区」，不放进池子，永远不会被自动分配，留给测试账号手动指定）
        │
新用户注册 ──▶ 触发器取「1000 以上、最小的空闲编号」→ 顺序递增 1000 / 1001 / 1002 …
        │
用户注销账号 ──▶ 该 uid 还回池子（变回空闲）
        │
下一个新用户 ──▶ 就拿到这个空出来的编号 ✅（因为取的是"最小空闲"）
```

- **保证不重复**：uid 在数据库里是主键，天然唯一；`profiles.uid` 也是 unique
- **默认名字**：用户没设昵称时，显示成 `小窝第 12 成员`（12 就是他的 uid）
- **顺序分配**（不是随机挑）：`order by uid` 取最小空闲，所以号是连续发的
- **注销后回收**：不是"永久占用"，编号会流转给后来的人
- **1~999 是保留区**：给测试账号手动指定用（SQL 模板在 `tools/supabase-schema.sql` 第 ⑪ 段）

## 四、隐私与安全设计

| 措施 | 说明 |
| --- | --- |
| **行级安全（RLS）** | 三张数据表都开了：每个人**只能 select/insert/update 自己那一行**，前端就算被改也读不到别人的数据 |
| **uid_pool 完全封闭** | 不给客户端任何策略，只有数据库触发器（security definer）能改 |
| **前端只带 Publishable key** | 这是公开的、受限的钥匙；Secret key 永远不碰前端 |
| **级联删除** | 注销账号时，资料 / 设置 / 对话记录一起删（`references auth.users on delete cascade`）|
| **秘钥默认不上云** | API Key 只在浏览器本地；用户勾选后才 AES-GCM 加密上传 |
| **注销只能删自己** | `delete_own_account()` 是 `security definer` 函数，内部只允许删 `auth.uid()` 那一行（前端不能删别人）|

> ⚠️ **RLS 策略（管"行"）和 GRANT（管"表"）是两层，缺一层就报 `42501 permission denied`。**
> 新版 Supabase 不会自动授予表权限，`tools/supabase-schema.sql` 第 ⑧ 段的 `grant ... to authenticated` 不能少。

## 五、前端已经实现的功能

| 功能 | 说明 | 主要位置 |
| --- | --- | --- |
| 登录后拉取云端资料 | 登录成功 → 依次拉 uid → profile → settings → 对话；uid 决定默认名字「小窝第 N 成员」| `main.js` `syncFromCloud()` |
| 保存时同时写云端 | 点「保存」→ 本地 + 云端各写一份，提示「已保存 ✓ 本地 + 云端都更新了」（云端失败不影响本地）| `user.js` + `cloud.js` |
| 设置 / 对话静默同步 | 改角色、聊天后自动同步；对话**防抖 3 秒**，不是每句都请求 | `settings.js` / `main.js` |
| **换账号不串台** | 本地存 `xingyue_last_user`（上次登录的账号 id），和这次登的 `user_id` 不一样就先清本地残留 | `main.js` `clearPreviousAccountData()` |
| **注销账号** | 个人中心底部危险按钮 → **密码 + 邮箱验证码**两项都过才删 → 删账号 + 清本地 + 释放 uid | `user.js` + `cloud.js` `deleteAccount()` → RPC `delete_own_account` |

> ⚠️ **注销是 RPC，不是 REST 删除**：Supabase 不允许前端 `DELETE /auth/v1/user`（会 405），
> 所以走数据库函数 `POST /rest/v1/rpc/delete_own_account`。
