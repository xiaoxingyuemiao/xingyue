## 二、进入网站的流程（首次 / 老用户 / 登录 / 游客）

```mermaid
flowchart TD
    A["打开网站"] --> B{"localStorage 里有<br/>xingyue_visited 吗？"}
    B -->|没有：首次访问| LOGIN["显示登录页<br/>auth-screen"]
    B -->|有：老用户| HOME["直接显示首页<br/>home-screen"]

    LOGIN --> C{"选哪个？"}
    C -->|登录 / 注册| CARD2["翻到第二张卡<br/>邮箱 + 验证码"]
    C -->|游客进入| GUEST["写 visited 标记<br/>进入首页（未登录）"]

    CARD2 --> OTP["发送验证码<br/>Supabase Auth（/auth/v1/otp）"]
    OTP --> MAIL["邮箱收到验证码<br/>（163 邮箱 SMTP 发出）"]
    MAIL --> VERIFY["输入验证码 → 登录"]
    VERIFY --> SAVE["凭证存本地<br/>xingyue_auth"]
    SAVE --> GUEST2["写 visited 标记<br/>进入首页（已登录）"]

    GUEST --> HOME
    GUEST2 --> HOME

    HOME --> D{"点左下角用户区"}
    D -->|未登录| LOGIN
    D -->|已登录| USR["user.html<br/>用户设置 / 退出登录"]
```

**关键点**：
- `visited` 只是「来过一次」的本地标记，**不代表已登录**（游客进入也会写）
- 老用户下次打开会**直接进首页**，要登录得自己点左下角用户区
- 登录页和首页是**同一个 HTML 文件**（`index.html`），靠 `display` 切换

## 三、登录流程（时序图）

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant P as 网页（index.html）
    participant S as Supabase Auth
    participant M as 邮箱（163 SMTP）

    U->>P: 输入邮箱 → 点「发送验证码」
    P->>S: POST /auth/v1/otp
    S->>M: 发验证码邮件
    M-->>U: 收到 8 位验证码
    U->>P: 输入验证码 → 点「登录」
    P->>S: POST /auth/v1/verify
    S-->>P: access_token + refresh_token + 用户信息
    P->>P: 凭证写入 localStorage（xingyue_auth）
    P->>P: 侧边栏用户区改为已登录状态
    Note over P: 每 30 分钟自动续期；过期时自动刷新
```

**当前登录能力**：邮箱验证码登录 / 自动续期 / 退出登录（在 `user.html` 最下方）
**当前还没有的**：找回密码、第三方登录（GitHub/QQ）、登录才能用的功能限制

## 四、首页功能流程

### 4.1 聊天流程

```mermaid
flowchart TD
    A["输入框输入 → 发送"] --> B["用户消息写入本地历史"]
    B --> C["组装请求<br/>系统提示 = 角色设定 + 情绪规则<br/>上下文 = 最近 N 对对话"]
    C --> D{"配置了 API 秘钥吗？"}
    D -->|没有| E["气泡提示：去设置页添加 API Key"]
    D -->|有| F["请求 API<br/>/chat/completions"]
    F --> G["得到回复"]
    G --> H["解析开头【情绪：X】标记<br/>正文去掉标记"]
    H --> I["角色回复写入本地历史"]
    I --> J["刷新常驻气泡<br/>（桌面 2 轮 / 手机 1 轮 + 10 秒消失）"]
    I --> K["Live2D 播放对应表情 / 动作"]
    F -->|失败| L["气泡提示：连接失败，去检查 API 配置"]
```

**要点**：
- 对话历史**只存在浏览器本地**（按角色分组），换设备就没了
- 上下文长度由设置页「角色记忆的对话对数」决定
- 情绪标记是**约定格式**：LLM 必须输出 `【情绪：开心】…`，Live2D 表情靠它驱动

## 六、流程里的「可改动点」（大改前先看这个）

| # | 现状 | 可以怎么改 |
| --- | --- | --- |
| 1 | 登录页和首页挤在一个 `index.html`，靠 `display` 切换 | 拆成两个页面，或用前端路由（hash 切换），代码更好维护 |
| 2 | **游客和登录用户能做的事几乎一样**（登录只是显示名字） | 加权限分层：未登录只能试聊 N 句 / 不能改角色 / 有广告位… |
| 3 | 老用户下次打开**跳过登录页**（visited 标记） | 改成"必须登录"，或"每次都显示登录页但记住账号" |
| 4 | 聊天记录只在本地 | 登录后同步到 Supabase 数据库（多设备同一份对话）|
| 5 | 用户资料（昵称/头像）只在本地 | 绑定到账号，换设备也能带过去 |
| 6 | 访客没有账号概念 | 加"注册"的独立流程（现在注册和登录是同一套 OTP）|
| 7 | 侧边栏菜单硬编码在 `index.html` | 改成数据驱动（像 `common.js` 那样），以后加页面只改一处 |
| 8 | 子页面之间是普通跳转，没有统一框架 | 保持轻量（零构建），但可以抽公共模板 |
| 9 | 只有一个"官方角色 + 我的角色"概念 | 可以扩展：角色商店 / 分享角色 / 导入别人的角色卡 |
| 10 | 聊天是纯文字 | 可以加语音（TTS 朗读 + 唇形同步，Live2D 已预留 LipSync 分组）|

## 八、改造进度

> 2026-09 确认的改造方向，**下面标记 ✅ 的已经上线**。

### 8.1 登录 / 注册（✅ 已完成）

进入网站**直接显示登录卡**（不再有"选择方式"那一张），三张卡之间互相跳转：

```mermaid
flowchart TD
    A["进站 → 登录卡"] --> B["方式一：邮箱 + 密码 → [登录]"]
    A --> B2["方式二：邮箱 + [发送] + 验证码 → [登录]"]
    A --> B3["[忘记密码？] → 找回密码卡"]
    A --> C["[没有账号？去注册一个吧] → 注册卡"]
    A --> G["[先随便逛逛] → 游客进首页"]

    C --> C1["[邮箱] + [密码] + [再次输入密码] + [验证码] + [发送] → [注册]"]
    B3 --> B4["[邮箱] + [验证码] + [发送] → [新密码] + [再次输入] → [重置密码]"]
    B4 --> A

    B --> H["进首页（凭证存本地，定时续期）"]
    B2 --> H
    C1 --> H
```

要点（都已实现）：
- 登录卡**同时支持密码和验证码**（卡内用「改用验证码登录 / 改用密码登录」切换）
- 密码规则：**至少 8 位且含字母和数字**，输入时实时校验；不符合才提示、符合则整行隐藏并把输入框描绿
- 每个密码框右侧有**小眼睛**（线条图标、无悬停效果、点击切换明文/密文）
- 注册卡 = 邮箱 + 密码 + 确认密码 + 验证码（验证码与「发送」按钮同一行、等高）
- **找回密码**：邮箱验证码 → 新密码（重置成功自动回登录卡并填好邮箱）
- 一张卡里「改用验证码登录 ｜ 忘记密码？」并排一行
- 技术：Supabase `signUp` / `signInWithPassword` / `verifyOtp` / `recover` / 修改密码（REST，零依赖）
